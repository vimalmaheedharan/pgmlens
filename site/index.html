Open-source program intelligence

Know when your program will really finish.

PGM Lens reads Jira, GitLab and GitHub, finds the work that is holding everything else up, and forecasts the finish date as honest probabilities instead of one hopeful date.

View on GitHub Try the demo in a minute

Three questions, answered first.

Every screen opens with the answer in plain language. The detail is one click away, not in the way.

When will it finish?

PGM Lens runs thousands of simulations on your team's recent pace and scope growth. You see a likely date, a date you can be 80% sure of, and the chance of hitting the deadline. A status is always a word and a shape, never just a colour.

What needs attention?

Declarative rules flag stale blockers, scope creep, overloaded owners, critical work nobody owns and long dependency chains. Each finding says what is wrong, why it matters and what to do next.

What is holding everything up?

A dependency map built from your real blocking links, with the critical path outlined. It surfaces the single issue at the root of a chain, so you fix that one first.

Built so you can check the maths.

Uncertainty is shown

Forecasts are probability bands, not a single date. Tick one box and the numbers behind every forecast appear.

AI explains, it does not invent

Executive briefings are written from numbered facts. A claim that cites no fact, or contains a number or issue key that is not in the facts it cites, is rejected and a plain briefing is used instead.

Rules are data

Risk thresholds live in a YAML file you can extend. Change what "stale" means for your team without touching code.

Works with the tools your teams already use.

Connectors turn each system into one normalized model, so a program that spans several trackers still reads as one.

Try it in a minute.

The demo ships with a realistic program that is deliberately behind schedule. You need uv and Node 20 or newer, or Docker.

# from source (works on Windows, macOS and Linux)
git clone https://github.com/vimalmaheedharan/pgmlens
cd pgmlens
uv sync
cd apps/web && npm install && npm run build && cd ../..
uv run python -m pgmlens_api --web apps/web/dist
# open http://localhost:8000   (with make: "make setup" then "make demo")

# or with Docker
docker compose up   # http://localhost:8080

Early, and honest about it.

PGM Lens is version 0.1. It is a solid core, not a finished product. Before you rely on it:

  • Storage is simple. Programs are kept in memory with a JSON file for persistence. A database is on the roadmap.
  • Forecasts count issues, not story points, and need a few weeks of history to be useful.
  • The API does not sync from Jira or GitLab by itself. That is deliberate, because a server that fetches arbitrary URLs is a security risk. Run a connector from the command line or your own job and send the result in.
  • Sign-in is a single token protecting write actions. Proper authentication is planned.
